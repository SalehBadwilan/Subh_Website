# تطبيق «صبح» — الموبايل (React Native / Expo)

تطبيق العميل لمنصة صبح — سوق سعودي متعدد التجار بإدارة مركزية.
هذا هو ناتج **اليوم 4** من خطة سباق الأسبوعين: تهيئة Expo، شاشات
Splash/Onboarding، تسجيل الدخول برقم الجوال + OTP، الشاشة الرئيسية،
والتنقّل السفلي — **بنفس هوية وبيانات تطبيق الويب**.

---

## التشغيل السريع

```bash
cd mobile
npm install        # مرة واحدة فقط
npx expo start     # ثم امسح رمز QR بتطبيق Expo Go (Android/iOS)
```

- **على المحاكي:** اضغط `a` (Android) أو `i` (iOS على Mac) بعد `npx expo start`.
- **على المتصفح (أسرع للمراجعة):** `npm run web` ثم افتح http://localhost:8081.
- **بيانات الدخول التجريبية:** أي رقم يبدأ بـ 5 (مثل `512345678`)، وأي رمز
  تحقق يعمل **ما عدا `000000`** (يُظهر رسالة الخطأ — نفس سلوك الويب).

## طبقة `src/shared` — للمشاركة مع فريق الويب

هذه الطبقة **مرآة** لملف `src/lib/customer-data.ts` في مشروع الويب:
نفس المنتجات والفئات والأسعار والأنواع (types) حرفيًا، حتى تكون الهوية
والبيانات واحدة على المنصتين.

| الملف | المحتوى | يعادل في الويب |
|---|---|---|
| `shared/types.ts` | نماذج البيانات (Product, Category, Order…) | أنواع `customer-data.ts` |
| `shared/mock-data.ts` | البيانات الوهمية نفسها | بيانات `customer-data.ts` |
| `shared/constants.ts` | حالات الطلب وثوابت OTP | `orderStatusLabels` وغيرها |
| `shared/validation.ts` | تحقق رقم الجوال السعودي | منطق `login.tsx` |
| `shared/api.ts` | طبقة API قابلة للتبديل mock/live | — (جديدة حسب الخطة §8) |

**خطة النقل إلى monorepo:** حسب خطة الـ Frontend (قسم 6)، عند توحيد
المستودعات ينقل هذا المجلد كما هو إلى `packages/shared` ويستورده الويب
والموبايل معًا. لهذا: استوردوا دائمًا من `@/shared` وليس من الملفات
الداخلية.

**التبديل إلى الـ API الحقيقي (اليوم 6):** كل دالة في `shared/api.ts`
موثّقة بالـ endpoint المقابل لها. ضع `EXPO_PUBLIC_API_MODE=live` في ملف
`.env` واستبدل جسم الدوال بنداءات فعلية — الشاشات لن تتغير.

## قرارات تقنية (مهم للفريق)

1. **RTL صريح بدون I18nManager:** الصفوف التي يهم ترتيبها البصري تستخدم
   `flexDirection: "row-reverse"` والنصوص `textAlign: "right"` (افتراضي في
   `AppText`). السبب: `I18nManager.forceRTL` يتطلب إعادة تشغيل التطبيق ولا
   يعمل بثبات في Expo Go — الأسلوب الصريح يعمل من أول تشغيل على كل
   المنصات. القوائم الأفقية تستخدم `FlatList inverted` لتبدأ من اليمين.
2. **الأرقام والهواتف LTR:** استخدم خاصية `ltr` في `AppText` لأي رقم
   (سعر، جوال، عدّاد) حتى لا ينقلب داخل النص العربي.
3. **الخط:** Cairo (نفس الويب) عبر `@expo-google-fonts/cairo` — استخدم
   `AppText` دائمًا ولا تستخدم `Text` مباشرة.
4. **الألوان والحواف:** من `lib/theme.ts` فقط — لا ألوان مكتوبة يدويًا.
   أي تعديل هوية يتم في الويب والموبايل معًا.
5. **التوكن في SecureStore** (وليس AsyncStorage) حسب متطلب الخطة، مع
   بديل localStorage على الويب.
6. **حماية المسارات:** مجموعة `(tabs)` محمية — الضيف يُعاد لتسجيل الدخول
   (يعادل `useRequireAuth` في الويب).
